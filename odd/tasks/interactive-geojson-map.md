# Interactive GeoJSON Map Filter

Objective: replace the reserved `map-placeholder.tsx` with a real interactive Chile GeoJSON map in `ContainerMapFilter` that works as a cross-filter (click a region → applies the Region filter and refetches the dashboard).
Branch: `feat/interactive-geojson-map` off `main` (6d7dfa2, live in production).
Delivery strategy: `ask-on-risk`, single slice; forecast ≈350–450 authored lines (asset excluded as generated).
Test runner: backend `npm test` (node --test via tsx); frontend has no runner → `npm run build` + `npm run lint` are the functional checks.

## Specs

- **S1** (user request, verbatim): "ya esta produccion al app, necestiamos añadir el tema de el mapa interactivo en geojson del frontend como uso de filtro interactivo genera un ODD para esto". Reading: the app is live (frontend Cloudflare Workers `accidentescarabineros.hveramtz-inf.workers.dev`, backend Fly `backend-dawn-meadowland-5739.fly.dev` + Neon); the map must render from GeoJSON and act as an interactive filter, not a decoration.
- **S2** Follow-up inherited verbatim from `odd/tasks/map-first-dashboard.md`: "replace `map-placeholder.tsx` with the real Chile vector map slice (GeoJSON source + library decision pending)". Scope for this slice: the 16-region choropleth layer (accidents per region, current period). Assumption (not a requirement): commune-level polygons are deferred — the catalog's commune ordinal ("XV-1") does not derive the 9-digit territorial comuna code (province-dependent), so a commune join needs a verified mapping table first. The placeholder's opaque white canvas — the predecessor's "deliberate plan-approved exception" — is superseded by S8.
- **S3** Map click is a filter control, fully synced with the dropdowns (same state, one source of truth):
  - Click region R → `filters.region = R.romanNumber`, `filters.commune = ALL_VALUE` ("Region change resets commune to keep the cascade coherent." — existing behavior in `dashboard-filters.tsx` must match).
  - Click the already-active region → clear to `ALL_VALUE` (toggle off).
  - Changing the Region dropdown updates the map highlight (bidirectional; no second selection state).
  - While a region is selected the map keeps the region layer: selected region emphasized, others dimmed; choropleth values always reflect the period (see S4), never the region selection itself.
- **S4** API change is additive only: `GET /api/dashboard` gains a complete territory series (e.g. `territories.all` with `{code, name, accidents, fatalities}` for all 16 regions at region scope / all communes of the region at commune scope) while `territories.items` keeps its current top-10 + `outsideTopCount`/`outsideAccidents`/`zeroAccidentCount` semantics untouched. Types updated in `backend/src/types/dashboard-api.ts` and `frontend/src/types/dashboard-api.ts`. The map layer colors from the full region series for the active period (frontend derives it with the period filters and region/commune cleared), so the choropleth stays correct when the user selects a region. Backend test asserts the additive shape and that zero-accident regions are included.
- **S5** GeoJSON is committed as a static bundled asset (finalized: `frontend/src/data/chile-regions.geo.json`), simplified to keep payload small; no runtime fetch to external geo hosts (no new CORS surface, deterministic builds). Join key (revised per T1 evidence, see L9): `properties.iso` (ISO 3166-2 region suffix, e.g. "AP", "NB") ↔ `abbreviation` in `frontend/src/data/oversio-identifiers.json` — 16/16 verified. Any region that fails to join must render as "no data" visibly, never crash or silently disappear.
- **S6** Interaction & a11y parity with the placeholder it replaces: functional zoom in/out controls (placeholder ships disabled `+`/`−` with `min-h-11 min-w-11` 44×44 targets — keep ≥44px), pan/zoom, hover tooltip (region name + accidents), keyboard-reachable regions (each region focusable; Enter/Space selects; visible focus ring), reduced-motion respected, no horizontal overflow at 375/768/1024/1440. `react-simple-maps` v5 documents `Geography` paths as `tabIndex={0}` by default and forwards SVG props, but does not promise Enter/Space activation; implement and verify that behavior rather than assuming focusability is sufficient.
- **S7** Production safety: existing dashboard behavior must not regress — dropdowns, KPIs, charts, Bearer barrier (`VITE_UUID_CONNECTION`), error/empty states. Checks: `cd frontend && npm run build && npm run lint`; `cd backend && npm test`. Deployment order is human-owned: backend (Fly) first is backward compatible (additive field), frontend (Cloudflare) second.
- **S8** (user requirement, verbatim): "sin fondo blanco, tiene que tener el mismo color de fondo que el background de la @frontend/ , si es posible fondo transparante asi nos ahorramos ponerle fondo". Acceptance: the map surface adds no background of its own — the app canvas shows through (`--background: #0a0b0d`, DESIGN.md layer 1, where "geospatial charts and topology graphs render directly onto this plane"). With the L3-final library this is native (the `<svg>` from react-simple-maps is transparent by default; the white was only the placeholder's own `bg-white`). If a tile-based engine is ever mounted here instead, its container default background must be explicitly overridden to transparent and no `TileLayer` added. Region fills, emphasis, "no data" and tooltip styling must be legible on the dark canvas using existing tokens (`--chart-*` on the plane; elevated flyout `#18191B`/95% + emerald glow for tooltips). The predecessor's white-canvas exception does not survive into production.

- **L3** Decisions:
  - **Granularity v1 = 16 regions.** Commune choropleth deferred: the 9-digit comuna code cannot be derived from `oversio-identifiers.json` ordinals (they are per-region, codes are per-province), so it needs a verified mapping table first — its own future slice.
  - **Library — react-simple-maps v5.** Best fit for this slice: it accepts a local GeoJSON `FeatureCollection`, renders each region as an SVG path, supports data-driven fills/click events, and includes pan/zoom via `ZoomableGroup`. The SVG is transparent by default, so S8 needs no map-canvas background or tile service. Official v5 docs report 34.3 KB gzip and React 19 support. Keyboard focus is built in; Enter/Space activation remains an explicit S6 implementation/verification requirement.
  - **Alternative — shadcn-map (tonghohin).** A useful shadcn-styled Leaflet toolkit when a tile basemap, markers, layers, search, or location controls are wanted. Its documented `MapTileLayer` defaults to OpenFreeMap vector tiles and falls back to OpenStreetMap raster tiles; the documented API does not provide a GeoJSON wrapper, so the choropleth would need React Leaflet's `GeoJSON` component composed directly. That is possible, but adds the tile-oriented toolkit to a no-tiles SVG-choropleth slice. See L7.
  - **Correction to earlier rationale:** React Leaflet v5 marks `GeoJSON.style` mutable; it can update styles declaratively. Do not reject Leaflet on the claim that recoloring necessarily needs manual `resetStyle`/`setStyle` loops. The deciding factors here are the desired no-tiles/local-GeoJSON SVG use case and the extra tile-focused shadcn-map layer, not an inability to restyle Leaflet.
  - **API shape:** additive `territories.all` (S4) rather than a new endpoint — one request per filter change stays the contract; `items` semantics untouched so current charts can't break.
